# 로또 자동 대시보드 — 백엔드

티스토리에 붙일 "로또 실시간 대시보드" 게시글이 스스로 최신화되도록 만드는 자동화 저장소입니다.
매주 **토요일 밤 9:30**, **월요일 아침 9시**(한국시간) 두 차례 동행복권 공식 데이터를 가져와
당첨번호 · 당첨점(명당) · 최신 뉴스를 갱신하고, 그 결과를 `docs/latest.json` 하나로 정리해둡니다.

티스토리 쪽 HTML은 이 `docs/latest.json`을 그냥 `fetch()`로 읽기만 하면 되고,
구글 시트나 Google Apps Script는 더 이상 필요 없습니다. (서비스 계정 키 같은 것도 전혀 안 씁니다.)

---

## 1. 처음 설정하는 방법

1. GitHub에서 **새 저장소를 만듭니다** (Public으로 만드세요 — Public이어야 `docs/latest.json`을
   외부 웹페이지에서 바로 읽을 수 있습니다. 인증정보를 안 쓰니 Public이어도 안전합니다.)
   - 기존 저장소를 재사용하실 거면, 안에 있던 `lotto_key.json` / `03_lotto_sheet_update.py` 등
     기존 파일을 전부 삭제하고 아래 파일들로 교체해주세요.
2. 아래에서 받은 파일/폴더를 저장소에 그대로 올립니다. **폴더 구조를 그대로 유지**해야 합니다.
3. 저장소 **Settings → Actions → General → Workflow permissions**에서
   **"Read and write permissions"** 를 선택하고 저장하세요.
   (이 설정을 안 하면 자동 커밋·푸시가 권한 오류로 실패합니다.)
4. 저장소 **Actions** 탭 → "로또 자동 업데이트" 워크플로우 선택 → **Run workflow** 로 한 번
   수동 실행해서 정상 작동하는지 확인하세요.
5. 성공하면 몇 초~1분 안에 `data/`, `docs/` 폴더에 커밋이 하나 생깁니다.
   아래 주소로 접속했을 때 JSON이 보이면 완료입니다:

   ```
   https://raw.githubusercontent.com/<본인 GitHub 아이디>/<저장소 이름>/main/docs/latest.json
   ```

6. 이 주소를 티스토리 HTML의 `API_URL` 자리에 넣으면 되는데, 이 부분은 제가 다음 단계에서
   기존 대시보드 HTML을 맞춰서 다시 드릴게요.

---

## 2. 폴더 구조

```
data/lotto_history.csv     당첨번호 전체 이력 (1~1236회 시드 포함, 이후 자동 추가)
data/shop_history.csv      당첨점 전체 이력 (1등·2등 포함, 1~1236회 시드 포함, 이후 자동 추가)
docs/latest.json           대시보드가 실제로 읽는 최종 결과물 — 자동 생성되니 직접 수정하지 마세요
scripts/update_lotto.py    매번 실행되는 본체 스크립트
requirements.txt
.github/workflows/update.yml
```

## 3. 동작 방식 요약

1. `data/lotto_history.csv`의 마지막 회차를 보고, 다음 회차가 이미 추첨됐는지 동행복권에 물어봅니다.
2. 추첨됐으면 당첨번호 + 1등/2등 당첨점을 가져와 두 CSV에 한 줄씩 이어붙입니다.
   (아직이면 — 예: 월요일 실행 시점엔 이미 반영돼 있어서 스킵 — 기존 데이터로 넘어갑니다.)
3. 구글 뉴스 RSS에서 "로또 당첨번호 1등" 관련 최신 뉴스 8건을 가져옵니다.
4. 최신 회차 정보 + 최근 50회차 원자료 + 이번 회차 1등 매장 리스트(누적 1·2등 횟수 포함) +
   뉴스를 합쳐 `docs/latest.json`으로 저장합니다.

## 4. 참고

- 구글 계정/서비스 키 등 외부 인증이 전혀 필요 없습니다.
- 예약된 GitHub Actions 워크플로우는 저장소에 60일간 아무 활동이 없으면 자동으로 꺼지는데,
  매주 커밋이 생기니 해당될 일은 없습니다.
- 기존 스크립트 대비 고친 점:
  - 1등만 수집하던 걸 **1등+2등** 모두 수집하도록 복원했습니다 (기존 이력 데이터엔 2등도 있었고,
    대시보드도 매장별 2등 횟수를 보여주는 구조라서요).
  - 매장 누적 횟수를 **판매점명이 아니라 판매점ID 기준**으로 계산하도록 고쳐서, 동명 매장이
    있어도 통계가 섞이지 않게 했습니다.
